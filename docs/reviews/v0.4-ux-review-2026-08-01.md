# UX/QoL Comprehensive Review — v0.4

**Date**: 2026-08-01  
**Scope**: Full command surface ergonomic review with ideal-state proposals  
**Constraints respected**: stateless, path-based, no login, no `.paperwork/`, files independent (v0_feedbacks)

---

## 1. Critical: `--from` Semantic Collision

**The single worst UX issue in the current CLI.**

Within `post` alone, `--from` means two completely different things:

```bash
paperwork post send thread.md "msg" --from alice    # --from = IDENTITY (who am I)
paperwork post read thread.md --from 3              # --from = RANGE START (seq N)
```

Same flag, same subcommand group, orthogonal semantics. An agent writing `post read --from alice` or `post send --from 3` gets a confusing type error instead of a clear "wrong flag" signal.

### Proposal

| Command | Current | Proposed | Rationale |
|---------|---------|----------|-----------|
| `post send` | `--from <NAME>` | `--as <NAME>` | "I act as alice" — actor declaration |
| `post edit` | `--from <NAME>` | `--as <NAME>` | Same |
| `post read` | `--from <N>` | `--from <N>` | Keep — range semantics natural here |

`--as` is unambiguous: it only ever means identity. `--from` is unambiguous: it only ever means range origin. No collision.

## 2. Identity Repetition Tax

Every `send` and `edit` requires explicit identity. A typical agent session:

```bash
paperwork post send standup.post.md "msg1" --from alice
paperwork post send standup.post.md "msg2" --from alice
paperwork post send standup.post.md "msg3" --from alice
paperwork post edit standup.post.md "fix" --seq 3 --from alice
```

`--from alice` repeated 4 times. The harness already knows who it is.

### Proposal: Environment variable fallback

```bash
export PAPERWORK_AGENT=alice   # set once at session start

paperwork post send standup.post.md "msg1"
paperwork post send standup.post.md "msg2"
paperwork post edit standup.post.md "fix" --seq 3
```

Rules:
- `--as` flag > `PAPERWORK_AGENT` env > error
- This is NOT login — env is process-scoped, transparent, caller-controlled
- Stateless: the CLI still doesn't store anything; the harness provides context
- Explicit override always available: `--as bob` for impersonation/testing

## 3. `post create` vs Auto-Create Ambiguity

Two ways to start a thread, with different behaviors:

```bash
# Way 1: explicit create (system message at #1, title, participants)
paperwork post create standup --title "Daily Standup" --participants alice,bob

# Way 2: auto-create on send (no system message, starts at #1 with real content)
paperwork post send quick-chat --from alice "Hey"
```

Problems:
- Agent doesn't know which to use
- `create` pollutes stream with system message → first real msg is #2
- `create` requires `--title` (mandatory), but auto-create has no title at all
- The system message `[Thread created: ...]` is not a real message; it's metadata pretending to be content

### Proposal: Kill `post create`, enrich first send

```bash
# Only way to start a thread: just send (with optional metadata)
paperwork post send standup --as alice "Hey team" --title "Daily Standup" --participants alice,bob,charlie
```

Desired CLI contract (implementation-agnostic):
- `--title` and `--participants` are optional metadata on first send
- No system message in the readable stream. `post read` shows first real message as #1.
- `post summary` returns title and participants correctly
- If no `--title` given, defaults to filename stem (`standup`)
- If no `--participants`, thread is open (anyone can send)
- `post create` is removed (or becomes a no-op alias for "send first message with metadata")

How the metadata is stored internally is a core implementation concern, not a CLI UX concern.

## 4. `--mention` Is Manual Redundancy

```bash
paperwork post send thread.md "@alice check this" --from bob --mention alice
```

The `@alice` is already in the body. Requiring `--mention alice` separately is:
- Redundant (agent types alice twice)
- Easy to forget (body says @alice but no `--mention` → no filter match)
- Divergent (body says @alice but `--mention bob` → which is truth?)

### Proposal: Auto-extract mentions from body

```bash
paperwork post send thread.md "@alice check this" --as bob
# CLI auto-detects @alice in body → records mentions: [alice]
```

- Parse `@(\w+)` patterns from body text
- Store in `- Mentions:` metadata automatically
- No `--mention` flag needed (remove it)
- If agent wants to mention without `@` in body (rare), keep `--mention` as optional override/addition

## 5. Argument Order: Path Dominance

Current:
```bash
paperwork post send <PATH> [BODY] --from <NAME>
paperwork post edit <PATH> [NEW_BODY] --seq <N> --from <NAME>
paperwork brief add <PATH> --entry <ENTRY>
paperwork contacts add <PATH> --profile <PROFILE>
```

Path is always the first positional arg. But in an agent's mental model, the ACTION and CONTENT come first; the file is just "where it goes". The path is infrastructure; the message is intent.

### Proposal: Content-first for send

```bash
# Current
paperwork post send standup.post.md "Parser done" --from alice

# Proposed (body as first positional, path as second or flag)
paperwork post send "Parser done" --to standup --as alice
```

However — this conflicts with the path-based stateless design where the file IS the primary noun. **Compromise**: keep path-first but support path omission when unambiguous:

```bash
# If only one .post.md in cwd, path is optional
paperwork post send "Parser done" --as alice
# → resolves to ./standup.post.md (or errors if multiple)
```

This is a QoL convenience, not a structural change. Full path always works.

## 6. `profile create` Redundant Name + Path

```bash
paperwork profile create agents/alice --name alice
```

The name `alice` appears twice: in the path and in `--name`. The filename stem IS the natural name.

### Proposal: Derive name from path by default

```bash
# Name derived from filename stem
paperwork profile create agents/alice
# → creates agents/alice.profile.md with name "alice"

# Override only when needed
paperwork profile create agents/alice-v2 --name alice
```

`--name` becomes optional (default: filename stem).

## 7. Flag Verbosity for Common Operations

```bash
# Current: add entry to brief
paperwork brief add onboarding.brief.md --entry "src/main.rs" --regex "fn main" --note "Entry point"

# Current: add contact
paperwork contacts add team.contacts.md --profile alice.profile.md
```

`--entry` and `--profile` are the primary payload, not optional modifiers. They should be positional.

### Proposal

```bash
# Brief: entry path as positional
paperwork brief add onboarding.brief.md "src/main.rs" --regex "fn main" --note "Entry point"

# Contacts: profile path as positional
paperwork contacts add team.contacts.md alice.profile.md
```

Flags are for optional modifiers. The thing you're adding is the argument.

## 8. Command Aliases

Agents type these commands thousands of times. No aliases = token waste.

### Proposal

| Full | Alias | Notes |
|------|-------|-------|
| `paperwork post` | `paperwork p` | Most frequent command |
| `paperwork profile` | `paperwork pr` | |
| `paperwork brief` | `paperwork b` | |
| `paperwork contacts` | `paperwork c` | |
| `paperwork validate` | `paperwork v` | |
| `post send` | `post s` | |
| `post read` | `post r` | |
| `post summary` | `post sum` | |

Single-char top-level, short abbreviations for subcommands. Full names always work.

## 9. `post summary` as Separate Command

`summary` is just a read mode — it reads the same file, just presents differently.

### Proposal: Merge into read

```bash
# Current
paperwork post summary standup.post.md

# Proposed
paperwork post read standup.post.md --summary
# or
paperwork post read standup.post.md --mode summary
```

Reduces command count. `read` is the verb; how you read is a flag.

Counter-argument: `summary` is semantically distinct enough to warrant its own command for discoverability. **Acceptable either way** — low priority.

## 10. `--reply-to` Implicit Mention Is Invisible

When bob replies to alice's message, the CLI auto-adds `mentions: alice`. But the agent doesn't see this happen:

```bash
paperwork post send thread.md "Sure!" --as bob --reply-to 2
# Output:
ok post.send #3 -> thread.post.md
seq: 3
```

No indication that alice was auto-mentioned. Agent might then ALSO pass `--mention alice` redundantly.

### Proposal: Surface implicit effects in output

```
ok post.send #3 -> thread.post.md
seq: 3
sender: bob
reply-to: 2
implicit-mention: alice
```

## 11. No Default `--limit` Indicator in Read Output

`post read` defaults to last 20 messages, but the output doesn't tell you this:

```
ok post.read 4 messages
---
#1 system ...
```

If there were 50 messages, you'd see 20 and think that's all.

### Proposal: Show window in status line

```
ok post.read 20/50 messages (showing #31-#50)
```

Or when all fit:
```
ok post.read 4/4 messages
```

## 12. Global Flags Noise in Help

Every subcommand help repeats `--json`, `--plain`, `-q`, `-h`. This is 4 lines of noise per command.

### Proposal: No change needed (clap convention)

This is standard clap behavior. Agents don't read `--help` often. Acceptable.

`paperwork completions <shell>` would help human operators. Agents don't need it, but the human persona (operator/reviewer) does.

### Proposal: Add `paperwork completions bash|zsh|fish|powershell`

Low priority. Human QoL only.

## 14. Suffix Auto-Completion Is Inconsistent

```bash
paperwork post send standup "msg" --as alice     # → standup.post.md ✓ (auto-suffix)
paperwork post read standup                      # → does this also auto-suffix?
paperwork validate standup                       # → does this?
```

### Proposal: Universal auto-suffix resolution

For ALL commands that take a path:
1. Try path as-is
2. If not found, try appending type suffix (`.post.md`, `.profile.md`, etc.)
3. If still not found, error

This means `paperwork post read standup` always works if `standup.post.md` exists.

---

## 15. `validate` Type Detection

`validate` relies on file suffix to know what parser to use. But:

```bash
paperwork validate myfile.md    # What type? Unknown suffix → ?
```

### Proposal: `--type` override flag

```bash
paperwork validate myfile.md --type post     # parse as post thread
paperwork validate myfile.md --type profile  # parse as profile
```

Default: infer from suffix. Fallback: error asking for `--type`.
