## 1. Changes from v0.2

| Dimension | v0.2 | v0.3 |
|-----------|------|------|
| File naming | Arbitrary `.md` names | Auto-suffix: `.profile.md`, `.post.md`, `.brief.md`, `.contacts.md` |

| Thread metadata | Bold-key (`**To**: all`) | Bullet-list (`- To: all`) |
| Message body | Raw Markdown (ambiguous boundary) | 4-backtick fenced code block (`````markdown ... `````) |
| Thread separator | `---` + H3 compound boundary | `---` sole separator (YAML-style) |
| Brief format | Bold-key entries | Bullet-list entries |
| Contacts format | Markdown table | Bullet-list |
| `profile list` | Listed ALL `.md` files | Filters by `.profile.md` suffix |
| `contacts read` | Default mode broken ("(no contacts)") | Fixed — renders correctly |
| New command | — | `validate <path>` |
| In-body `---` | Collision risk with separator | Safe: use `***` convention; body fenced |

## 3. Bugs

### BUG-1: `validate` accepts any content as valid (Critical)

**Severity**: Critical — the command's sole purpose is defeated  
**Repro**: `echo "garbage" > x.post.md && paperwork validate x.post.md`  
**Expected**: `✗ Invalid: ...` with structural issues listed  
**Actual**: `✓ Valid: x.post.md`  
**Root cause**: Likely only checks file existence / suffix, not actual format parsing.

### BUG-2: `post read --plain` ignores `--from`/`--to` range

**Severity**: Medium  
**Repro**: `paperwork post read thread.post.md --from 6 --to 6 --plain`  
**Expected**: Raw content of only message #6  
**Actual**: Dumps the entire file from the beginning  
**Note**: Default (non-plain) mode correctly filters by range.

### BUG-3: Empty message body accepted without warning

**Severity**: Low (carried from v0.2)  
**Repro**: `paperwork post send thread.post.md "" --from alice`  
**Expected**: Error or warning  
**Actual**: `✓ Post #5 sent` — empty fenced block appended

### BUG-4: Contacts "summary" field always empty

**Severity**: Low (carried from v0.2)  
**Design ref**: v0_feedbacks: "显示各个路径加上各个路径上的profile简介"  
**Expected**: `contacts read` reads referenced profile and populates summary  
**Actual**: `"summary": ""` in JSON; no summary in default output

## 4. UX Assessment

### 4.1 Improvements over v0.2

| Aspect | Assessment |
|--------|-----------|
| **Auto-suffix** | Excellent UX — type `alice` get `alice.profile.md`. No ambiguity about file type. Enables `profile list` filtering. |
| **Fenced code block bodies** | Solves the body-boundary problem definitively. `---`, `###`, bold text, `***` inside body are all safe. |
| **Bullet-list metadata** | Cleaner raw file readability. Proper Markdown list semantics. |
| **`---` sole separator** | Industry-standard (YAML multi-doc). Simpler parsing. |
| **`profile list` fixed** | Now actually useful — filters by suffix. |
| **`contacts read` fixed** | Default mode renders correctly. |
| **`validate` command** | Good concept — agents can verify file integrity before consuming. |
| **`brief read --full`** | Nice progressive disclosure: TOC default, `--full` for detail. |

### 4.2 Remaining Weaknesses

| Aspect | Issue | Suggestion |
|--------|-------|-----------|
| **`validate` is a no-op** | Accepts garbage. Destroys trust in the command. | Actually parse the file per its suffix type; report specific structural failures |
| **System message at #1** | `post create` still injects `[Thread created: ...]` as seq #1. Off-by-one cognitive tax persists. | Seq 0 or metadata header outside message stream |
| **`post summary` sparse** | No title, no participants, no creation time in output. | Surface metadata from system message |
| **`post read` default hides timestamps** | Only JSON has time info. | Show dimmed timestamps in default mode |
| **No `--stdin` for bodies** | Multi-line bodies require shell quoting. Fenced format makes this more important (bodies are code blocks). | Add `--stdin` flag |
| **No `--no-color` / `NO_COLOR`** | Agents piping output may get ANSI. | Standard practice |
| **Windows `✗`/`→` encoding** | Still renders as `?` in Windows terminal stderr. | ASCII fallback or UTF-8 stderr enforcement |
| **`profile show` default ≠ raw format** | Default shows a re-rendered view (bold-key style), not the actual bullet-list file. `--plain` shows truth. | Default should render the actual format with color |
| **`profile list --json` is flat paths** | Returns `["path1", "path2"]` — no structured objects with name/model. | Return `[{"path": ..., "name": ..., "model": ...}]` |

## 7. Recommendations (Priority Order)

1. **Fix `validate`** — must actually parse and reject structurally invalid files. This is the highest-impact bug; a broken validator is worse than no validator (false confidence).
2. **Fix `post read --plain` range filtering** — `--from`/`--to` should apply in plain mode too.
3. **Reject empty body** — minimum: warn; ideal: error with "use `--stdin` for empty/multiline".
4. **Add `--stdin`** — fenced code block format makes multi-line bodies common; shell quoting is painful.
5. **Reconsider system message at #1** — persistent UX friction.
6. **Enrich `post summary`** — title, participants, creation time.
7. **Populate contacts summary** — read referenced profile descriptions.
8. **Add `--no-color` + `NO_COLOR`** — standard practice for pipe-friendly CLI.
9. **Fix Windows encoding** for `✗`/`→`.
10. **`profile list --json`** — return structured objects, not flat paths.
