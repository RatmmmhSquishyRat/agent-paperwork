## 1. 背景与范围

### 1.1 用户对 v0.4 格式的批评要点

依据 `docs/researches/format-v2-design-synthesis-2026-08-09.md` §1.2（其上游为 `v0_feedbacks.md` 第 23 行与 `research-repo-formats-2026-08-08.md` §6 技术债清单）：

- 信息结构组织不够"正规"：存在多处自造 pattern——`---` + "2 行内前瞻 H3"复合边界、非 ASCII 消息头分隔符 `·`（U+00B7）、`—` 空值占位、`all` 魔法值、固定 4 反引号围栏——缺乏 Markdown 原生语义依据。
- system 消息以 `[Thread created: X | participants: Y]` 正文文本编码元数据，`post summary` 靠字符串切分反解，属脆弱编码（技术债 #2）。
- `validate` 校验深度不足：seq 连续性与围栏闭合校验已实现却未接入命令路径（技术债 #1）。
- `Message.to` 格式层存在但 CLI 无入口（技术债 #3）；非 ASCII 结构符与 v0.4 输出协议 ASCII 化方向不一致（技术债 #4）。

用户最高指令原文（`v0_feedbacks.md` 第 23 行）："既然我们选择使用md作为文件格式, 那么就以正规简洁的方式组织信息结构, 严谨克制, 但是自由灵活地使用各个标题, 列表等等语法."；第 27 行确立 fence 包裹用户正文为硬性要求（保留，仅标准化）。

### 1.2 两项关键裁决（synthesis §1.3）

1. **元数据载体**：纯原生 Markdown（标题/段落/列表/链接/围栏），**禁止** YAML frontmatter、禁止新增 YAML 依赖。
2. **兼容策略**：项目默认不向前兼容，**hard breaking v0.5**，CHANGELOG 附迁移指南，不做 migrate 命令。

### 1.3 v0.5 交付内容概览

**四格式新 schema 要点**（spec.md §2 统一设计语言，经 R1–R15 裁决修订后的定稿）：

| 构造 | v0.4（废除） | v0.5（定稿） |
|-----------|--------------|--------------|
| 文档身份 | 各格式不一 | H1 = name/title；H1 后首个 H2 前段落 = description（四格式均适用，含 post，R5） |
| 扁平标量属性 | 大写键 `- Model:`、`—` 占位、`all` 魔法值 | 小写 ASCII 键 `- key: value`，三处有效区（preamble / post 消息属性区 / brief 条目属性区，R4）；空/缺省即省略该行 |
| 消息边界 | `---` + 前瞻 H3 `### #N sender · ts` | fence 感知的 H2 文法头 `## #N sender (ts)`，正则 `^##\s+#(\d+)\s+([^\s()]+)\s+\((.+)\)\s*$`（R1/R9） |
| 用户正文 | 固定 4 反引号围栏 | 动态围栏 max(3, 正文最长连续反引号串 + 1)，仅适用 post 消息正文（R15） |
| profile Scope | 大写键 + 反引号 glob | 属性行列表 `- <perm>: <glob>`，键可重复（R3 否决 GFM 表格） |
| 参与者 | system 消息文本编码 | preamble 属性行 `- participants: alice, bob`（R2 否决 `## Participants` 保留标题） |
| contacts 条目 | 裸路径 bullet | Markdown 链接 `- [label](path)`（含 `[](<path>)` 转义形式，R11 label 取目标 profile H1、回退文件名主干） |
| brief 条目 | `## Entries` 包装 + H3 + blockquote note | 条目直接 H2 + 属性行 + 裸散文 note；hash 全量 64 位 hex；` ```regex ` 逃生口保留 |
| 线程元数据 | `post create` 注入 system 消息 #1 | `post create` 删除；`post send --title/--participants` 锁内首写 preamble；`post summary` 直读 preamble |

**命令面变化**：删除 `post create`；`post send` 新增 `--title`/`--participants`/`--to`；`validate` 接入 seq 连续性（seq gap → category `validation` 直出）与动态围栏闭合校验，并新增疑似消息头启发式 warning（R9/R10）；空 `.post.md` 文件由 v0.4 的 `ok` 变为 `error format:`。

**测试规模**：回归验证 144 测试 = core format 内联 28 + core ops 69 + CLI 集成 47（见 §5）。

## 6. 已知限制与残留问题

以下各项均为规格明文接受或已文档化的残留，不构成发布阻碍：

### ISSUE-1: 尾扫缓冲起点切断围栏奇偶的残留限制

**Severity**: Low（有兜底）
**来源**: spec §5.5 明文声明；R6 裁决记录（design §8.2）。
**说明**: `read_last_seq_locked` 的 64KB+256B 缓冲区内已做 CommonMark 长度规则的开合追踪，但缓冲区起点之前的围栏奇偶状态不可知（缓冲起点可能恰好切断围栏），该构造下 fence 内伪造候选头仍可能污染 seq。
**兜底**: `validate` 的 seq 连续性校验事后暴露（BDD:CONC-03）；末条消息 ≤64KB 上限（I3）保证真实头必然完整落入缓冲。

### ISSUE-2: `thread_edit` 锁内截断 + 重写的崩溃窗口

**Severity**: Low（spec 已接受）
**来源**: spec §5.7 崩溃窗口声明；Grace m-7；design §7 措辞校准（C6）。
**说明**: `thread_edit` 的 `set_len(0)` + `write_all` 中途断电/杀进程会丢失全文件（含 preamble）。fs2 排他锁已排除并发写者，仅断电/杀进程暴露。
**后续方向**: 锁内 temp+rename（需评估 fs2 锁与 inode 替换交互，本次不做）。

### ISSUE-3: brief hash 换行敏感

**Severity**: Low（仅文档化，不修复）
**来源**: spec §6.4（技术债 #5 处置）；不变量 I7。
**说明**: hash 对目标文件原始字节计算（SHA-256 全量 64 位 hex），跨平台换行符转换会导致误报 Shifted。行为与 v0.4 一致，spec 中文档化声明。

### ISSUE-4: 工作区残留 `target-review/` 构建产物目录

**Severity**: Low（卫生问题）
**说明**: 评审进程使用独立 `--target-dir` 产生的构建产物目录（含 `debug/`、`smoke/` 等），非交付物。
**建议**: 删除该目录（不影响任何构建与测试）。

### ISSUE-5: v0.4 旧文件读取呈静默空结果

**Severity**: Low（防护已覆盖写路径）
**来源**: Daniel m3；CHANGELOG L152。
**说明**: `post read` 作用于未迁移 v0.4 线程返回 `ok` + 0 messages，`contacts read` 返回空列表（旧构造不获解析支持，宽容解析忽略）。读路径无错误信号可区分已迁移/未迁移。
**防护**: 写路径已由 M2 修复兜住——向未迁移线程 `post send` 直接 `error format:` 拒绝，不再产生混合格式损坏；迁移完成度可用 `validate`（报 `error format:`）机器检查。
