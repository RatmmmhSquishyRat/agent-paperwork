## 1. Changes from v0.4

| Dimension | v0.4 | v0.5 |
|-----------|------|------|
| Identity/payload args | `--from/--name/--title/--entry/--profile/--seq` flags | Positional: `<PATH>` always 1st; `<NAME>` 2nd for send/edit; content always last |
| `--from` semantics | Dual (sender in send/edit, seq in read) — U-01 conflict | Only `post read`, only seq range; identity is positional NAME |
| Usage errors | clap default output, exit 2 | Standard envelope `error usage:` + fix + canonical example, exit 2 (7th category) |
| Runtime errors | exit 1, six categories | Unchanged (exit 1; format/validation/io/not-found/already-exists/not-allowed) |
| `--help` / `-V` | exit 0 | Passthrough preserved: exit 0, never usage envelope |
| Path resolution | `ensure_suffix` unconditional rewrite (`standup.md` → `standup.post.md` even when `standup.md` exists) | Three-level: ① original path if it is an existing file; ② suffixed path if it exists; ③ suffixed path as operation target |
| Foreign `.md` hit | Silently rerouted to suffixed path | Level ① hit parsed by type parser → `error format:`, no reroute |
| `post send` output | seq/path/sender | Adds singular `implicit-mention: <name>` only when reply-to implicit mention fires |
| `post read` output | `showing` only when truncated | `showing: n/total` always (total = post-filter, pre-limit) + `window: #first-#last` (absent when empty) |
| Error JSON | no `command` key | Adds `command` key; usage errors carry `exit_code: 2` |
| `validate` | suffix inference only | Adds `--type post|profile|brief|contacts` override |
| Aliases | `p/b/c/v` hidden | Adds `po` for post; `p/b/c/v` unchanged |
| File format / core API | — | Zero change (verified: same `---` boundaries, `### #N sender · timestamp`, four-backtick fences) |

## 3. Bugs

### BUG-1: Non-ASCII characters reintroduced into machine-facing error output (em dash / middle dot)

**Severity**: Medium (regression of the v0.4 R-09 ASCII-safe baseline; no functional impact)  
**Repro**: `paperwork post send standup.post.md --from alice "hi"` (any removed-flag call), or `paperwork post send notes.md alice "hi"` on a non-thread `.md`  
**Expected**: all envelope text pure ASCII (v0.4 guarantee; agents on legacy Windows consoles, e.g. CP936/CP437, must not see mojibake)  
**Actual**: usage-envelope fix line contains U+2014 EM DASH (`...v0.5 grammar — give the value as a positional argument`); the no-subcommand default message inherits the about text's em dash; the CLI-layer format fix contains U+00B7 (`### #N sender · timestamp headers`). On non-UTF-8 consoles these render as `?` (observed during testing). The same U+2014 also leaks into `--json` usage errors' `fix` field.  
**Root cause**: literal non-ASCII in source strings — `repos/paperwork-cli/src/main.rs:170` (em dash in migration-teaching fix), clap `about` text sourced from the Cargo description, and `repos/paperwork-cli/src/cmd/post.rs:190` neighborhood (middle-dot fix string). Core-layer equivalents correctly use ASCII (`.`).  
**Fix suggestion**: replace `—` with `;`/`-` and `·` with `.` in CLI-layer strings; keep non-ASCII only inside managed file content (which is UTF-8 by contract).

> **Status: FIXED in 39156db, re-verified 2026-08-09.** QA 复核（重建 release 二进制后原始字节审计）：usage 迁移教学 fix 行（`--from`/`--seq` 等全部旧 flag 面）与异型文件 format fix 行（`sender . timestamp`）均为纯 ASCII（stdout/stderr 非 ASCII 字符计数 = 0）；`--json` 档 usage 错误的 `fix` 字段同样纯 ASCII；about 文本 em dash 亦已改为 ASCII（`--help` 同步受益）。R-09 ASCII-safe 基线恢复。

### BUG-2: No-subcommand default envelope message is the about text, not a usage-error description

**Severity**: Low  
**Repro**: run `paperwork` with no arguments (default mode)  
**Expected** (S-OUT-06): stderr first line of the form `error usage: missing subcommand`  
**Actual**: `error usage: Stateless, file-based collaboration CLI for AI agents — everything is a file, append-only, human-readable` followed by fix/example. The `--json` path for the same invocation correctly says `requires a subcommand but one was not provided` — the two output modes disagree on the message for the identical error.  
**Root cause**: `usage_message()` (main.rs) takes the first line of clap's rendered error; with zero argv tokens clap renders the about line first, while the presence of a recognized flag (`--json`) changes the render shape. Special-casing `ErrorKind::MissingSubcommand` would align both paths.

> **Status: FIXED in 39156db, re-verified 2026-08-09.** QA 复核：裸调用 `paperwork` → `error usage: missing subcommand: expected one of profile, post, brief, contacts, validate`；裸组调用 `paperwork post` → `missing subcommand for group 'post'; run 'paperwork post --help' to list its verbs`（DisplayHelpOnMissingArgumentOrSubcommand 同形处理）；默认档与 `--json` 档消息逐字一致，均 exit 2、纯 ASCII，符合 S-OUT-06。

## 5. UX Assessment

1. **Grammar coherence achieved**. PATH-first / NAME-second-for-actor-verbs / content-last is uniform across all 18 commands; there is no longer any command-specific argument ordering to memorize. The `--from` identity/range collision (U-01, the single most confusing aspect of v0.2–v0.4) is structurally gone — misusing `--from alice` in read is now a type error at parse time.

2. **Errors teach migration for free**. Every old-grammar invocation (`--from/--seq/--name/--entry/--profile`) lands in a usage envelope with a canonical, copy-paste-executable v0.5 example. An agent upgrading from v0.4 needs zero external docs to self-correct on first failure. This is the strongest UX property of the release.

3. **Exit-code layering is clean and verifiable**: 0 success / 1 runtime (six categories) / 2 usage. The F1 ruling (PATH+single-string → validation exit 1, missing NAME → usage exit 2) behaves exactly as adjudicated, including the NAME-slot teaching in the validation message.

4. **Three-level path resolution fixes a real v0.4 foot-gun** without breaking auto-creation: existing foreign `x.md` is never silently rerouted (format error instead), bare names still resolve to suffixed files, and write commands still create at the suffixed location. All eight S-PATH scenarios pass.

5. **Additive output fields are well-judged**: `implicit-mention` makes a previously invisible side effect observable (default + JSON parity); `showing`/`window` remove the "was I truncated?" guesswork, with the post-filter/pre-limit total being the correct denominator (verified 20/25).

6. **Rough edges found in the first QA round (BUG-1/BUG-2, §4 items) were all fixed in 39156db and re-verified**, including two bonus hardenings: `post summary` on a missing thread now reports `not-found` (was empty summary), and `post edit` on a foreign `.md` now reports `format` like send does. Machine parseability of the envelope itself is intact: `^ok `/`^error <category>:` + `fix:` + `example:` lines are stable.

| Aspect | v0.3 | v0.4 | v0.5 |
|--------|------|------|------|
| Grammar learnability | Ad-hoc flags | Ad-hoc flags + dual-meaning `--from` | One positional rule for all commands |
| Error actionability | Hint only | category + fix + example | + usage category + migration teaching + exit 2 |
| Self-correction on upgrade | n/a | n/a | Errors themselves teach the new grammar |
| Path handling foot-guns | present | present (unconditional rewrite) | three-level, verified |
| Output visibility | partial | good | side effects (implicit mention, window) exposed |
