## 1. Architecture Summary

v1 is a ground-up redesign from v0. Core shifts:

| Dimension | v0 | v1 |
|-----------|----|----|
| State model | `.paperwork/` managed workspace + `.agent` identity file | Fully stateless, path-based |
| Setup | `init` + `invite` required | None — files auto-create on first use |
| Identity | Implicit "current agent" | Explicit `--from` on every send/edit |
| Communication | Separate `dm` (1:1) + `post` (group) | Unified `post` primitive (participant-agnostic) |
| Knowledge briefs | `manifest` command | Renamed to `brief` |
| Notifications | `notify` command + `notifications/` files | Removed — @mentions are message metadata; query via `post read --mention` |
| Scope query | `who --owns/--reads/--writes` | Removed |
| File interdependency | Managed cross-references via contacts/layout | None — files are fully independent |

**Command surface**: `profile`, `post`, `brief`, `contacts` — 4 top-level commands.

## 4. Bugs

### BUG-1: `contacts read` default mode renders "(no contacts)"

**Severity**: High (core feature broken in primary output mode)  
**Repro**: `contacts create x.md && contacts add x.md --profile p.md && contacts read x.md`  
**Expected**: Table showing the contact entry  
**Actual**: `(no contacts)`  
**Note**: `--json` and `--plain` work correctly — parsing is fine, default renderer is broken.

### BUG-2: `profile list` returns all `.md` files without format validation

**Severity**: Medium (usability, incorrect results)  
**Repro**: Place post/brief/contacts files in same dir as profiles, run `profile list <dir>`  
**Expected**: Only files parseable as profiles  
**Actual**: All `.md` files listed (posts, briefs, contacts, auto-created threads)  
**Impact**: In a real working directory, this command is unusable for its intended purpose.

### BUG-3: Concurrent send reports wrong seq in confirmation

**Severity**: Low (file content is correct; only the stdout confirmation is wrong)  
**Repro**: Run 3 `post send` commands in true parallel (separate processes)  
**Expected**: Each confirmation shows the seq actually assigned  
**Actual**: Confirmations showed #3, #4, #2 while file has #2, #3, #4  
**Root cause**: Seq computed before lock acquisition; actual assignment happens under lock.

### BUG-4: Empty message body accepted without warning

**Severity**: Low (no data corruption, but pollutes thread)  
**Repro**: `post send thread.md "" --from alice`  
**Expected**: Error or warning  
**Actual**: `✓ Post #5 sent` — empty message appended

### BUG-5: Contacts "Summary" column never populated

**Severity**: Medium (feature incomplete per design intent)  
**Design reference**: v0_feedbacks: "contact就是一个特殊的brief, 从cli读的时候, 显示各个路径加上各个路径上的profile简介"  
**Expected**: `contacts read` reads each referenced profile and shows its description  
**Actual**: Summary column always empty string

## 5. UX Assessment

### 5.1 Strengths

1. **Zero-friction statelessness**: No setup, no workspace, no identity file. `post send <path> "msg" --from x` works from anywhere on any path. Maximum ad-hoc usability for agent harnesses.

2. **Explicit identity eliminates ambiguity**: `--from` makes every operation self-contained. No hidden state to corrupt or confuse.

3. **Unified Post primitive**: One command for 1:1 and group. No path derivation logic, no separate DM storage. Participant count is irrelevant to structure.

4. **Filter-based notification replacement**: `post read --mention alice` and `--reply-to N` provide targeted querying without a separate notification system. Simpler, composable, no extra file types.

5. **Auto-creation on send**: Connectionless — first message to a new path creates the thread. No prerequisite `create` needed (though `create` adds title/participants metadata).

6. **Brief verify pipeline**: 3-state (Fresh/Shifted/Stale) with clear symbols (`✓`/`~`/`✗`). `--base-dir` for flexible resolution. Solid.

7. **`--plain` = true raw content**: Correctly outputs on-disk bytes. Enables `paperwork post read x.md --plain | diff - expected.md` workflows.

8. **Self-edit guardrails**: Only final message, only own message. Clear error messages for both violations.

### 5.2 Weaknesses

1. **System message at #1**: `post create` injects `[Thread created: ...]` as seq #1. Every real message starts at #2. This creates:
   - Permanent off-by-one cognitive tax
   - `--reply-to 1` accidentally replies to system, not first human message
   - Pollutes `post read` output with non-conversational content
   - **Suggestion**: Use seq 0 or a metadata header outside the message stream

2. **`profile show` default mode is not "rich Markdown"**: Default strips `## Scope` heading and backtick-quoting, producing a flat view. `--plain` shows the actual rich file. The modes feel inverted — default should be the rich rendering.

3. **No `--stdin` for message bodies**: Multi-line Markdown bodies require shell quoting. Agent harnesses often generate multi-line content. The v0 UX design specified `--stdin`; it's absent in v1.

4. **No `--no-color` flag / `NO_COLOR` support**: Agents piping output may get ANSI codes. No way to disable.

5. **`post summary` is sparse**: Missing title, participants, creation timestamp. Only shows path, count, last sender, snippets. The system message at #1 contains this info but it's not surfaced.

6. **`post read` default hides timestamps**: Only JSON has timestamps. Default output has no time information — agents can't reason about recency without `--json`.

7. **Brief file header says `# Manifest:`**: Raw file uses `# Manifest: <title>` but CLI calls it "brief". Naming inconsistency between file format and command surface.

8. **Windows `✗`/`→` encoding**: These render as `?` in Windows terminal (stderr). `✓` and `~` work fine. Likely a codepage issue with specific Unicode characters.

9. **`profile list` has no useful output format**: Default just prints paths (one per line). No table with name/model/description. `--json` returns a flat string array of paths, not structured objects.

## 6. File Format Verification

### Profile (`alice.md`)
```markdown
# alice

**Model**: gpt-4o  
**Description**: Parser module implementer

## Scope

**Read**: `src/**`  
**Write**: `src/parser/**`  
**Owns**: `src/parser/**`
```
✓ Human-readable, regex-parseable, backtick-quoted globs.

### Post thread (`standup.md`)
```markdown
---

### #1 — system · 2026-08-01T04:21:12Z

**To**: all  
**Reply-To**: —

[Thread created: Daily Standup | participants: alice, bob, charlie]

---

### #2 — charlie · 2026-08-01T04:21:24Z

**To**: all  
**Reply-To**: —
**Mentions**: alice  

@alice nice work! I'll update the docs.

---
```
✓ Boundary-anchored format (`---` + H3). Bold-key metadata. Body-safe.

### Brief (`onboarding.md`)
```markdown
# Manifest: Codebase Onboarding

**Author**: alice  
**Created**: 2026-08-01T04:23:32Z  
**Description**: How to understand this project quickly

## Entries

### main.rs

**Path**: `src/main.rs`  
**Hash**: `42b664743ddb6056ca84ab76bcf57d71533713c1bed9a493e8c0e787709e0540`  
**Regex**: `fn main`  
**Groups**: —

> Entry point of the application

---
```
✓ Structured entries with hash + regex. Note: header says "Manifest" not "Brief".

### Contacts (`team.md`)
```markdown
# Contacts: Core Team

| Path | Summary |
|------|--------|
| c:\...\alice.md |  |
| c:\...\bob.md |  |
```
✓ Table format. Note: Summary column empty (BUG-5). Stores absolute paths.

## 7. Comparison with v0

| Aspect | v0 | v1 | Verdict |
|--------|----|----|---------|
| Setup friction | High (init + invite) | None | v1 wins decisively |
| Identity clarity | Fragile (`.agent` file, mutable externally) | Explicit (`--from`) | v1 wins |
| 1:1 vs group | Two separate systems | One primitive | v1 simpler |
| Notification | Separate files + command | Filter on read | v1 more composable |
| Discoverability (`who`) | Built-in | Removed | v0 had utility; v1 relies on agents knowing paths |
| Portability | Tied to workspace | Any path, any location | v1 wins |
| File interdependency | Managed cross-refs | None | v1 more robust |
| Output polish | Better default rendering | Sparse defaults | v0 slightly better |
| `--stdin` for bodies | Designed (not verified) | Absent | Regression |
