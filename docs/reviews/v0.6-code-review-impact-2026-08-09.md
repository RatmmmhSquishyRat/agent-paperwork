## Minor Issues (CONSIDER)

### m-1 Windows smoke 的 `post edit` 断言可能空跑假 PASS
[.github/workflows/ci.yml#L154](c:/Users/15480/Desktop/AIWorkshop/repos/agent-paperwork-wt-v06grammar/.github/workflows/ci.yml)

**Problem**：本轮新增的 Windows 侧 edit 断言 `& $BIN post edit ... | Select-String "^ok post.edit"` 在失配时 Select-String 不抛错、无输出、步骤继续（`$ErrorActionPreference = "Continue"`，pwsh 不因原生命令非零退出而失败），与 unix 侧 `set -e` + grep 失配即失败不对称。旧文法 usage 断言因显式校验 `$LASTEXITCODE -eq 2` 不受影响。此弱点为既有 harness 模式（其余 Select-String 行同源），本轮新增行继承之。

**Fix**：为新增断言补守卫，如 `if (-not (& $BIN post edit ... | Select-String "^ok post.edit" -Quiet)) { Write-Error "FAIL: edit"; exit 1 }`；或后续统一以 `Run-Assert` 辅助函数硬化整个 pwsh 块。
