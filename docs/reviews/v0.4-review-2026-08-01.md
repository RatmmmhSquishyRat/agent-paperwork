## 1. Changes from v0.3

| Dimension | v0.3 | v0.4 |
|-----------|------|------|
| Success output | `✓ Profile created: <path>` | `ok profile.create <path>` + structured fields |
| Error output | `✗ <msg>` / `→ <fix>` (garbled on Win) | `error <category>: <msg>` + `fix:` + `example:` |
| JSON structure | Bare payload (array/object) | Wrapper: `{"status":"ok","command":"...","conclusion":"...",...}` |
| JSON errors | `{"error":"...","hint":"...","exit_code":1}` | `{"status":"error","category":"...","message":"...","fix":"...","example":"...","exit_code":1}` |
| `--stdin` | Absent | Added: `post send <path> --from x --stdin` |
| Empty body | Accepted silently | Rejected: `error validation: message body is empty` |
| `validate` | No-op (accepted garbage) | Real parsing: rejects invalid files with specific structural errors |
| `--plain` + range | Ignored `--from`/`--to` | Correctly filters |
| `contacts read` | Summary always empty | Populated: reads profile name + description |
| `post summary` | Path + count + snippets only | Adds title, participants, last.sender/time/snippet |
| `post read` default | No timestamps | Shows `#N sender timestamp` + inline `reply:#N mentions:x` |
| `profile list --json` | Flat path array | Structured: `[{"name","model","path"}]` |
| `profile list` default | Paths only | `name (model)` per line; graceful `(unreadable)` for corrupt files |
| `-q` behavior | Suppress all confirmation | Suppress `ok` status line; still outputs structured fields |

## 4. Remaining Issues

### ISSUE-1: `post summary` title field is raw system message body

**Severity**: Low (cosmetic)  
**Observed**: `title: [Thread created: Daily Standup | participants: alice, bob, charlie]`  
**Expected**: `title: Daily Standup`  
**Note**: The system message body is `[Thread created: <title> | participants: <list>]`. Summary should parse out just the title.

### ISSUE-2: `brief read --full` doesn't show entry details

**Severity**: Low  
**Observed**: `--full` shows `main.rs: src/main.rs` (same as default but with path)  
**Expected**: Should show hash, regex, note per entry (as v0.3 did)  
**Note**: `--plain` shows all details in raw Markdown. `--full` lost the detail rendering.

### ISSUE-3: System message at #1 persists

**Severity**: Low (design choice, carried from v0.2)  
**Observed**: `post create` injects `[Thread created: ...]` as seq #1  
**Impact**: First real message is #2; `--reply-to 1` accidentally replies to system  
**Mitigation**: Auto-created threads (via `post send` to new path) don't have this — start at #1 with real content

### ISSUE-4: No `--no-color` / `NO_COLOR` support

**Severity**: Low  
**Note**: Less impactful now since error output uses ASCII-safe `error`/`fix`/`example` format. Success uses `ok`. No Unicode symbols in critical paths anymore.

## 5. UX Assessment

### 5.1 Major Improvements

1. **Structured output protocol**: `ok <command> <conclusion>` + key-value fields is machine-parseable without JSON. Agents can regex `^ok ` for success, `^error ` for failure, and extract fields line-by-line. This is a significant ergonomic win for harness integration.

2. **Error taxonomy**: `error <category>:` (not-found, not-allowed, validation, format) gives agents a machine-readable failure class without parsing prose. Combined with `fix:` and `example:`, errors are fully actionable.

3. **`--stdin`**: Eliminates shell-quoting pain for multi-line bodies. Combined with fenced code block format, agents can pipe arbitrary Markdown safely.

4. **`validate` works**: Agents can now verify file integrity before consuming. The specific error messages (`no valid message boundaries found`, `missing agent name heading`) enable self-repair.

5. **Contacts with summaries**: `contacts read` now shows `alice (Parser module implementer)` — agents can discover who's who without opening each profile.

6. **`post read` default shows timestamps + metadata**: No longer need `--json` just to see when messages were sent or who they reply to.

7. **`-q` semantics refined**: Suppresses only the status line, keeps structured fields. Enables `paperwork -q post send ... | grep seq:` patterns.

### 5.2 Overall Maturity Assessment

| Aspect | v0.2 | v0.3 | v0.4 |
|--------|------|------|------|
| Core mechanics | ✓ | ✓ | ✓ |
| File format | Bold-key (fragile) | Fenced+bullet (robust) | Same (stable) |
| Output protocol | Ad-hoc `✓`/`✗` | Same | Structured `ok`/`error` + fields |
| Machine parseability | `--json` only | `--json` only | Default output is parseable + `--json` |
| Error actionability | Hint only | Hint only | Category + fix + example |
| Validation | None | Broken (no-op) | Working |
| Agent ergonomics | Basic | Good | Strong |

v0.4 is the first version where the CLI feels **designed for agent consumption** rather than merely tolerable. The structured output protocol eliminates the need to always use `--json`, reducing token cost for harnesses.

## 6. Recommendations (Priority Order)

1. **Parse title from system message** — `post summary` should show `Daily Standup`, not the raw `[Thread created: ...]` wrapper.
2. **Restore `brief read --full` detail** — show hash, regex, note per entry (regression from v0.3).
3. **Consider removing system message** — or move to seq 0 / metadata header. The auto-create path (no system msg) is cleaner.
4. **Add `--no-color`** — low priority now that output is ASCII-safe, but still standard practice.
