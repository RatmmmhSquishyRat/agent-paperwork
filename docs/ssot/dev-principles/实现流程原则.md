# 实现流程原则

适用于任何非小型重构、非小型模块的实现。由 Main Agent 在编排实现时驱动执行。

## 实现前文档

依据相关 SSOT 与 pillars，必须产出五份文档：`spec`、`design`、`BDD`、`TDD`、`impl_plan`。

同时为该实现者单独产出 `role` 文档，至少包括：对外工作职责、工作原则、`BOOTSTRAP` 等。

上述全部文档必须完全符合相关 SSOT 与 pillars。相关 SSOT 或 pillars 变更时，必须完整检查并更新这些文档。

## 实现门槛

文档给出后，不得直接开始实现。

必须使用第三方视角的批判性 subagents，从多种 distinct 初始视角，依据相关 SSOT 与 pillars，对相关文档做完整 review 与对抗性辩论，并进入 review-rework loop。

直到全部文档完全符合相关 SSOT 与 pillars 并闭合后，才可开始实现。
