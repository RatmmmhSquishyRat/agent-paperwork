## 一、owner 指令原文要点

### (1) 接受 action-first 槽位顺序

owner 在听取三个研究员（简洁可维护 / agent 效率 / 最小变更三视角）的重评估汇报后裁决：

> 我大概明白了, 看来action first是cli中的基本设计, 那么我接受你们的这个设计.

即：`paperwork <组> <动词> ...` 的槽位顺序保留；path-first 字面文法（含组内路径先行的折中形态）维持否决（复评论证见研究文档 §5）。

### (2) NAME/BODY 改为具名必填 flag，短形式授权自行设计

> 但是name这里确实会和content歧义, 因此我们改为不定位置的必选参数, 也就是用户名使用--author这个全称, 内容使用--message这个全称, 然后简称自己设计.

即：名字（NAME）与内容（BODY）均不再占用位置槽，改为**不定位置的必选（必填）具名 flag**；全称由 owner 指定为 `--author` 与 `--message`；短形式（简称）授权实现方自行设计。

### (3) 本轮不发布

> 我没让你发布0.6, 你现在功能都还没有稳定下来

即：本轮**不 bump 版本号、不打 tag、不 publish crates.io、不写 CHANGELOG 发布段**；仅做文法修正的设计、实现与治理文档落盘，发布时机由 owner 另行指示。

## 二、指令解读（落盘时点共识）

### 2.1 新文法规则

1. **位置参数仅剩 PATH**：全 CLI 任何命令只保留一个位置参数 PATH（目标文件路径，恒必填，第一位）；NAME 与 BODY/MESSAGE 一律不占位置槽。
2. **必填与可选一律具名 flag**：NAME（`--author`）、内容（`--message`）及各命令主载荷（title / entry / seq / profile 路径等）全部为具名 flag；必填 flag 缺省落 usage 信封（exit 2）。v0.5 规则 3（「必填即位置参数」判据）废止于本轮。
3. **flag 唯一语义**：同一命令内任何 flag 只有一种含义；跨命令 `--to` 为显式登记的类型判别例外（post send = 收件人名单字符串列表 / post read = seq 上限 u64，clap 类型强制互不混用）（rework 轮编排层裁定 F1 改写；初稿「post send 的 `--to` 已随 D2 裁决删除，不再存在」表述更正：format-v2 已随 0.5.0 发布，send `--to` 保留不改名）。`--from` 仅存于 post read 且仅表 seq 起点。
4. v0.5 规则 1 中「PATH 恒第 1 必填」保留；「NAME 第 2 必填位置参数」与「content 恒末位」废止。

### 2.2 短形式裁定记录

owner 授权短形式自行设计；编排层裁定如下：

| flag | 短形式 | 理由 |
|---|---|---|
| `--author` | `-a` | 全称首字母；全 CLI 唯一 |
| `--message` | `-m` | git `commit -m` 行业惯例，agent 迁移直觉成本最低 |
| post read `--mention` | 无短形式 | 避免 `-m` 在同一组（post）内双义 |
| 其余全部 flags | 无短形式 | rework 轮编排层裁定 F3：短形式收窄为仅 `--author/-a`、`--message/-m` 与既有全局 `-q`；此前实现方设计的一切其他短形式（`-r/-p/-t/-l/-d/-o/-n` 等）全部收回为仅长形式，消除跨命令多义 |

### 2.3 `--message` 与 `--stdin` 互斥语义

- 两者同时给出：stdin 优先生效，但 CLI 必须显式拒绝该组合，报 **usage 错误（exit 2，category usage）**，显式优于隐式，不做静默择一。
- 仅给 `--stdin`：正文从标准输入读取（多行大片内容的首选通道，承接 v0_feedbacks #3.1 便于书写的精神）。
- 仅给 `--message`：正文取 flag 值；以 `-` 开头的正文不再需要 `--` 边界保护（flag 值由 clap 绑定，无位置槽混淆面）。
- 两者皆缺：落 usage 信封（exit 2），example 展示 `--author` + `--message` 完整形态。（裁定补记 2026-08-09，rework 轮编排层裁定 F2：本条初稿「落 validation 错误（exit 1）」系 clap 层判定机制明确前的初步解读；正文通道缺失与缺 `--author` 同构，归 usage exit 2，由 clap `required_unless_present` 组合在解析层判定（MissingRequiredArgument），命令层无需管道；以 spec §3.1/§5 为准。）

### 2.4 逐命令新签名表

| 命令 | v0.6 签名 | 备注 |
|---|---|---|
| post send | `<PATH> --author <NAME> (--message <BODY> \| --stdin) [--reply-to N] [--mention a,b] [--title T] [--participants a,b] [--to a,b]` | `--title/--participants/--to` 为建线程载荷（send 自动建线程时生效；对既有线程静默忽略，行为登记见 spec §3.1）。裁定补记（rework 轮编排层裁定 F1/F6）：本行此前勘误「`--participants`/`--to` 已随 format-v2 D1/D2 裁决废除、不得复活」更正为保留：format-v2 已随 0.5.0 发布，`--to`（收件人名单）保留不改名（规则 3 类型判别例外，§2.1），`--participants` 一并保留；本轮不改其运行时行为 |
| post read | `<PATH> [--from N] [--to M] [--mention X] [--reply-to N] [--limit 20]` | `--mention` 无短形式（§2.2）；`--from/--to` 仅表 seq 范围 |
| post summary | `<PATH>` | 不变 |
| post edit | `<PATH> --author <NAME> --seq <N> (--message <NEW_BODY> \| --stdin)` | 三重护栏（wrong sender / not most recent / not final）不变 |
| profile create | `<PATH> --name <NAME> [--model] [--description] [--scope-*]` | 保留 `--name` 具名必填 flag（补记：本行初稿曾误录为 `--author`，经编排层 task #12 裁定更正；owner 的 NAME/BODY 歧义裁决仅针对 post 含正文动词，profile 名字不与 content 同槽，不在 `--author` 适用范围） |
| brief create | `<PATH> --title <T> [--owner] [--description]` | title 由位置参数收编为必填 flag（规则 2.1-2） |
| brief add | `<PATH> --entry <E> [--regex] [--note]` | 同上 |
| brief remove | `<PATH> --entry-title <T>` | 同上 |
| contacts create | `<PATH> [--title]` | title 有默认值，保持可选 flag |
| contacts add | `<PATH> --profile <P>` | profile 路径由位置参数收编为必填 flag |
| validate | `<PATH> [--type post\|profile\|brief\|contacts]` | 不变 |

profile show / profile edit / profile list / brief read / brief verify / contacts read 均为单位置参数 PATH + 可选 flags，本轮不涉改动。
